# Code of conduct

OpenITSM aims to be useful to organizations and contributors with different backgrounds and levels of experience.

Participants should:

- Treat others respectfully and discuss technical disagreements constructively.
- Use clear, relevant communication and credit others' work.
- Respect privacy, ownership, licenses and organizational confidentiality.
- Keep issues and pull requests focused on the project.

Harassment, threats, discrimination, impersonation, doxxing, spam, and publication of private credentials or personal data are unacceptable.

The maintainer may edit or remove inappropriate public content, restrict participation, or decline contributions. Enforcement should consider context and explain decisions where doing so does not expose private information. A fair community does not require tolerating abuse.

For a non-sensitive conduct concern, describe the behavior briefly without identifying private details. Sensitive conduct concerns require a verified private maintainer channel. That channel has not yet been configured; do not publish private allegations, personal information or security details as a workaround.

Security vulnerabilities follow [SECURITY.md](SECURITY.md), not a public conduct discussion. Before the community is opened publicly, the maintainer must establish a working private route for sensitive reports.

This policy applies to the project's issues, pull requests and other project-managed community spaces. It is an original project policy; it does not claim affiliation with an external code-of-conduct program.
