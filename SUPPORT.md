# Support

OpenITSM currently provides an engineering preview with community-oriented maintenance, not a production support contract or guaranteed response time.

## Ordinary questions and bugs

Start with [README.md](README.md), the [operational runbook](docs/P1_07_RUNBOOK.md), and [test commands](docs/P1_06_TESTING.md). When the GitHub repository is available, use its bug or feature request form for non-sensitive issues.

Include the candidate/version, operating system, Python/browser versions, expected behavior and a minimal synthetic reproduction. Sanitize logs and screenshots. Avoid uploading database files, secrets, asset inventories, internal hostnames or organization/user records.

The verified environment is Windows x64 / CPython 3.14.7 with the checked-in Windows hash locks. Other platforms may be explored, but are not certified by the recorded results.

## Security and sensitive reports

Follow [SECURITY.md](SECURITY.md). Do not use a public bug form for vulnerabilities or private data. Private vulnerability reporting has been selected but is not enabled or verified by this local preparation.

## Requests outside current scope

Production deployment, real-site migration/restore, organization SMTP/identity integrations, sustained capacity, multi-process/proxy/network storage, and full browser/accessibility certification require separate assessment. Community discussion does not imply these are implemented or supported.

The connected account rolandcobi and existing private repository rolandcobi/OpenITSM have been verified read-only. No support portal, email address, discussion board or hosted repository has been created by these documents.
